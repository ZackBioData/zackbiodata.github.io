Deployment Models

Public Cloud

  • All workloads/projects hosted on a cloud service provider (CSP) such as AWS.
  • Cloud-native model: infrastructure fully managed in the provider’s environment.
  • Examples: startups, SaaS products (Dropbox, etc.).
  • Networking: typically mix of public + private subnets within AWS VPC.

Private Cloud

  • Infrastructure hosted on-premises (datacenter owned by organisation).
  • Can be managed using OpenStack or similar.
  • Suitable for sensitive workloads:
    • Hospitals (patient data).
    • Government (classified systems).

Hybrid Cloud

  • Mix of on-prem + cloud.
  • Linked with VPNs or Direct Connect.
  • Common when organisations already own a datacenter but want to expand into cloud.
  • Example: Legacy finance/government platforms.

Cross-Cloud (Multi-Cloud)

  • Using multiple cloud providers for one project.
  • Examples: Amazon EKS ↔︎ Azure Arc ↔︎ GCP Kubernetes Engine.
  • Avoids vendor lock-in, increases resilience.
  • Complex to manage but increasingly common in enterprise IT.

AWS Accounts & Permissions

  • Root account: Created when signing up for AWS (used rarely, high risk). ✅ Made.
  • IAM accounts: Best practice → create IAM users with least-privilege permissions. ✅ Made.
  • Permissions & policies: Assign roles and groups instead of using root.
  • If billing mistakes happen, AWS Support can reduce or refund charges.

Innovation & Transformation

Kondratiev Waves

  • Concept of long-term innovation cycles (waves of technological change).
  • Cloud adoption seen as part of the most recent “digital” wave.

Burning Platform

  • Business strategy term: abandoning outdated systems (“on-prem”) for survival.
  • In cloud: moving from legacy infrastructure → cloud-native.
  • Digital transformation guides highlight how to manage this change and mitigate resistance.

Evolution of Computing

  • General-purpose computing: Intel Xeon processors, traditional CPUs.
  • Elastic Compute Cloud (EC2): AWS on-demand compute service.
  • GPU computing: AWS Inferentia, EC2 GPU instances for ML/AI workloads.
  • Quantum computing: AWS Braket (managed service for quantum simulators + hardware).

Key Takeaways

  • Deployment models: Public = cloud-native, Private = on-prem, Hybrid = bridge, Multi-Cloud = multiple CSPs.
  • IAM setup is critical → root account should NOT be used beyond initial setup.
  • Cloud adoption framed as part of larger innovation waves and often driven by burning platform fear.
  • Compute evolution continues beyond EC2 → GPU and quantum workloads.
